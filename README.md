# Tilawa

A 29-day Qur’an reading plan, split by surah, with page-by-page progress.
EN/ID, light/dark, no account, progress saved in the browser.

## Run locally

```bash
npm install          # once: Tailwind CLI
node dev.js          # http://localhost:5500 · reloads the browser on save · rebuilds CSS while you edit
```

Open it through the server, not as a file: the browser only loads the WebAssembly core over http.

## Project layout

| Path | What it is |
|---|---|
| `index.html` | The page markup, styled with Tailwind classes |
| `styles/app.css` | Tailwind source: colour tokens (light/dark), fluid type, breakpoints, animated bits |
| `styles/build.css` | Compiled CSS the page loads (generated by Tailwind, committed) |
| `js/main.js` | Entry: loads the text + the Rust app, starts everything |
| `js/schedule.js` | Carousel around the day cards, "don't skip" bubble |
| `js/hero.js` · `js/extras.js` | Hero moon, accordion/share/Saweria |
| `js/state.js` · `js/boot.js` | Shared helpers · pre-paint theme script |
| `lang/en.jsonc`, `lang/id.jsonc` | All text, one file per language (JSON + `//` comments; edit and reload, no rebuild) |
| `quran.json` | Start page of every surah (Mushaf Madinah, 604 pages) |
| `crates/tilawa-core/` | Rust: the 29-day plan and progress rules (plain library, `cargo test`) |
| `crates/tilawa-app/` | Rust + Leptos: day cards, progress header, EN/ID language, light/dark (uses `tilawa-core`) |
| `pkg/` | `tilawa-app` compiled to WebAssembly (generated, committed) |
| `dev.js` | Dev server with auto-reload + Tailwind watch |

Generated files are committed so GitHub Pages can serve the repo as-is. After editing,
`npm run build` (or just keep `node dev.js` running for CSS) before you commit.

## Rust migration

Moving to Rust step by step.

- [x] **Phase 1** – plan + progress rules in Rust (`tilawa-core`), called from the existing JS through WebAssembly
- [x] **Phase 2** – schedule cards rendered with Leptos (`tilawa-app`); JS keeps the header, carousel and bubbles
- [x] **Phase 3** – progress header, language, theme in Leptos; text as JSON
  - [x] progress header (count, line, bar, two-tap reset) in `header.rs`
  - [x] language switch + `data-i18n` text (`i18n.rs`, `page.rs`), text in `lang/*.jsonc`
  - [x] theme switch (`theme.rs`; `js/boot.js` still applies the saved pick before paint)
- [ ] **Phase 4** – full Leptos CSR app built with `trunk`; old JS removed
- [ ] Phase 5 (optional) – Rust API on Vercel, only if a feature needs a server

### Working on the Rust core

```bash
cargo test                                   # run the rules' unit tests (no browser needed)
npm run build:wasm      # = wasm-pack build crates/tilawa-app --target web --release --out-dir ../../pkg --no-pack
```

Rebuild `pkg/` after changing anything in `crates/`, then refresh the page.
Needs the `wasm32-unknown-unknown` target (Arch: `pacman -S rust-wasm wasm-bindgen wasm-pack`, same version as `rust`).
